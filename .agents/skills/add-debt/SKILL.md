# Log JASON-OS Technical Debt

Append one technical-debt item to `.planning/DEBT_LOG.md`. This is the current
lightweight debt log; it preserves a durable routing signal until a dedicated,
guarded debt system is approved.

## Use this skill when

- Research or review identifies a debt candidate that needs a durable record.
- A limitation, shortcut, risk, or shortcut-shaped decision should not be lost.
- The user wants to record technical debt without opening a full debt system.

## Do not use this skill for

- Cross-session task tracking: use `todo`.
- Bug reports or feature requests: file a GitHub issue.
- Plan deferrals with activation triggers: retain them in the plan until they
  are deliberately promoted to a todo or debt item.

## Procedure

1. Gather or propose the following fields from the conversation, then ask the
   user whether the proposed row looks right before writing:
   - Title: short and actionable.
   - Severity: `S0` blocking, `S1` high, `S2` normal, or `S3` nit.
   - Category: for example security, performance, UX, documentation, porting,
     or hygiene.
   - Notes: what the debt is, why it exists, and what paying it off means.
2. Ensure `.planning/DEBT_LOG.md` exists. If it does not, create it with this
   header:

   ```markdown
   # Debt Log

   <!-- Generated by /add-debt stub (v0.1). Upgrade trigger: see SKILL.md. -->

   | ID | Title | Severity | Category | Notes | Filed |
   | --- | --- | --- | --- | --- | --- |
   ```

3. Determine the next identifier as one greater than the maximum existing
   `D<N>` value, or `D1` when the log is empty. Never reuse a deleted ID.
   Escape every user-supplied pipe as `\|`, append exactly one row, and use
   today's date in the Filed column.
4. Echo the saved row to the user for confirmation.

## Guardrails

- Append only. Do not silently overwrite, edit, or delete existing debt rows.
- Never include secrets, tokens, credentials, or other sensitive content.
- If the user rejects the proposed row, do not write it.

## Upgrade trigger

Replace this lightweight log only after an approved dedicated debt system
provides at least one of the following:

- A guarded debt-intake CLI with a durable source of truth.
- Severity propagation that surfaces urgent debt during normal operation.
- Deliberate links between debt items and remediation todos.
- A volume of entries that makes the Markdown table impractical.

Any redesign must use the normal port-analysis process; do not silently change
the storage model.

## Done when

One user-confirmed, correctly escaped row was appended and shown to the user.
